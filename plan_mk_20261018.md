## 2. Non-destructive ground rules

1. **Branching.** `git remote add upstream git@github.com:debpalash/VoiceStudio.git`. `main` tracks upstream (fast-forward only). All work on `ext/*` branches: `ext/fish-api`, `ext/qwen3-tts`, `ext/qwen3-train`. Merge `upstream/main` into each regularly to avoid drift.
2. **New code in new places.** Only new files/packages (`backend/engines/fish_api/`, `backend/engines/qwen3_tts/`, `backend/training/`, `docs/engines/*.md`). Edits to existing files limited to registry one-liners, `models.yaml`/licence data, docs index, i18n.
3. **Inert by default.** Each engine reports `is_available() == (False, reason)` until configured. Default engine stays `omnivoice`. Nothing downloads or phones home without a click.
4. **Isolation.** Fish = plain HTTPS (`httpx`/`requests` already in the tree; avoid adding `fish-audio-sdk` to the app venv). Qwen3 and training = own venv, as MOSS does.
5. **Data compatibility.** No Alembic changes unless unavoidable; prefer `settings_store` keys and files under the data dir (`omnivoice_data/…/finetune/`). If a table is needed, add one new migration with an upgrade/downgrade test.
6. **Revertable.** Each phase = a branch whose removal leaves the app identical to upstream.
7. **Tag a baseline** (`git tag mk-baseline-20261018`) before starting, and run the existing test suite once to record what is already red.

## 3. Phase 1 — Fish Audio API (cloud, opt-in)

### 3.1 API facts (verify before coding; docs were mid-migration when checked)
- REST: `POST https://api.fish.audio/v1/tts`, `Authorization: Bearer <key>`, a **`model` request header** (`s2.1-pro`, `s2-pro`, `s1`; omitted/unknown falls back to `s2.1-pro` per the migration page), JSON body with `text`, `reference_id` (saved voice) or inline references, `format`, `latency`, `chunk_length`, etc.
- Streaming: WebSocket TTS with the same `model` header.
- Python SDK: `fish-audio-sdk`, `from fishaudio import FishAudio`, `FISH_API_KEY` (reference only).
- Other Fish APIs to wrap later in the same package: voice model create/list/delete (cloning from user audio), ASR, credit/usage.
- **Confirmed from docs (2026-10-18):**
  - `POST https://api.fish.audio/v1/tts`; headers `Authorization: Bearer`, `Content-Type: application/json` (or `application/msgpack`), `model:`. Supported models: `s2.1-pro` (recommended, also the default if the header is omitted or unknown) and `s2-pro`. `drama-3` is brand new (week of 2026-10-18) and **confirmed valid** as the REST `model: drama-3` header on the same `/v1/tts` request shape; mark it "new" in the dropdown. Its `reference_id` may be an array (one voice per speaker) for multi-speaker text. Tag syntax: `[delivery direction]` before words, `[shaky breath]`/`[small laugh]` sounds and pauses inline, paired tags `<whisper> <emphasis> <soft> <fast> <slow> <stress> <forceful>`, experimental `<french>…</french>` language switch, `<|phoneme_start|>…<|phoneme_end|>` phonemes (CMU Arpabet / pinyin / romaji), `<|speaker:0|>` speaker tags. No stated limits or pricing. `s1` is being phased out (retires 2026-12-31): ignore it, don't expose it. `s2.1-pro-free` is a $0 tier without latency guarantees: optional.
  - Body: `text`, `reference_id`, `references` (list of audio + transcript; 10–30 s clean sample recommended, no hard limit stated), `format` (`mp3` default, `wav`, `pcm`, `opus`), `mp3_bitrate` (64/128/192), `sample_rate`, `opus_bitrate`, `prosody{speed 0.5–2.0, volume}`, `latency` (`balanced` | `normal`), `chunk_length` (100–300, default 200), `temperature`, `top_p`, `repetition_penalty`, `max_new_tokens`, `normalize`, `language` (BCP-47; only affects normalization/timestamps; max 35 chars or HTTP 400; not in the SDK).
  - Response: raw audio bytes (no JSON on success).
  - Errors are JSON `{message, status}`: 400 bad params / missing voice; 401 bad key; 402 out of credits; 403 key scope; 404 model/voice not found; 429 rate or **account concurrency limit**; 5xx server. Retry only 429 and 5xx with exponential backoff. Edge 413/5xx may be non-JSON.
  - Python SDK exceptions (reference): `AuthenticationError`, `RateLimitError`, `NotFoundError`, `APIError`, `FishAudioError`.
- **Voices (REST, same base URL, Bearer auth):** `GET /model` (list; `self`, `page_size`, `page_number`, `title`, `tags`, `language`; omit `self` for the public Voice Library; returns `total`, `items`, `has_more`), `GET|PATCH|DELETE /model/{id}` (`visibility`: `private` | `unlist` | `public`), `POST /model` to create a saved voice (multipart: `voices` audio files .wav/.mp3/.m4a/.opus, optional `texts` transcripts, `title`, `enhance_audio_quality` default true, `train_mode` default `fast`; `state`: `created`/`trained`/`failed`). Instant clone = inline `references` on `/v1/tts` (SDK shows it, raw HTTP shape for `references` is not documented; it takes audio bytes + `text`, so confirm msgpack vs JSON/base64 before relying on it; saved voices via `reference_id` avoid the question).
- **Cloning guidance:** ≥10 s clean mono single-speaker audio; 1–2 min improves fidelity; no hard max stated.
- **Privacy:** never default a created voice beyond `private`; the create/upload action needs the explicit confirm described in §3.3.
- Still open: S2.x emotion/control tags (separate Emotions page, not read); pricing and concurrency numbers; wire format of inline `references`. Default model setting: `s2.1-pro`. The model setting drives which tag helpers the UI offers (S2.x natural-language vs. `drama-3` brackets/paired tags).
- Sources: [TTS docs](https://docs.fish.audio/features/text-to-speech.md), [Python SDK](https://docs.fish.audio/sdk-reference/python/text-to-speech), [migration](https://docs.fish.audio/developer-guide/getting-started/migration).

### 3.1b Python-first approach (author codes mainly in Python)
- **All Fish logic lives in the Python backend.** Phase 1 ships with zero required Electron/React work: configure via env vars (`FISH_API_KEY`, `OMNIVOICE_TTS_BACKEND=fish-audio`) or `settings_store`, and drive it through the existing FastAPI routes (`/generate`, longform, stories) and the OpenAI-compatible route (`backend/api/routers/openai_compat.py`). The Settings panel in §3.3 becomes a later, optional step.
- **Transport: plain `httpx` + JSON against `/v1/tts` (decided after reading the docs, 2026-10-18).** The SDK always sends a model and defaults to `s2-pro`, has no documented way to pick `s2.1-pro`, and doesn't expose the `language` field. Raw REST gives full control, adds no dependency (so no `uv tree` conflict risk, no optional extra), and JSON works (msgpack is optional). Keep the SDK as an optional reference only; revisit if its model/language params are documented. Map errors ourselves (table in §3.1).
- **Fast iteration loop in pure Python:** a `scripts/fish_smoke.py` (not at repo root) that calls `client.py` directly, then pytest with the HTTP layer stubbed; no UI needed to develop or verify.
- **Fish's own agent resources** ([coding-agents page](https://docs.fish.audio/developer-guide/resources/coding-agents)):
  - Skills: `npx skills add https://docs.fish.audio` installs two: `fish-audio-sdk` (Python/JS SDK signatures, sync/async, model selection, exceptions) and `fish-audio-api` (raw REST/WebSocket, auth, MessagePack/JSON/multipart, streaming protocol). Use `--list` first, `--skill fish-audio-sdk -a claude-code` to install just one. It writes to `.agents/skills/` and `skills-lock.json`, so run it on `ext/fish-api` only and commit the lock change with it. Read the `SKILL.md` files first (`/.well-known/agent-skills/<name>/SKILL.md`); they are third-party content.
  - `https://docs.fish.audio/llms-full.txt` is the full docs in one file. Use it to close the open items in §3.1 (S2.1 `model` header, emotion tags, reference limits) and `/api-reference/errors` for the 401/402/429 mapping.
  - MCP server `https://api.fish.audio/mcp` (OAuth; voice search, TTS, transcription). Useful as a dev-time aid in Claude Code only; do **not** ship it in the app (it would be a second, unmanaged cloud path).

### 3.2 Design
```
backend/engines/fish_api/
  __init__.py   FishAudioBackend(TTSBackend)   id="fish-audio"
  client.py     thin HTTPS client: tts(), list_voices(), create_voice(), ping()
  config.py     resolve_base_url / model / key (env > settings_store), like asr openai-compat
docs/engines/fish-audio.md
tests/backend/engines/test_fish_api.py   (stubbed HTTP; no network, no key)
```
- `FishAudioBackend`: `gpu_compat=()`/CPU-only semantics (no local model → must never trigger GPU eviction or model-load budgets; `ensure_ready` = no-op). `supports_voice_design=False` initially; `supports_emotion` set once tag syntax is verified. `supported_languages=["multi"]`, `instruct_vocabulary="freeform"`.
- Cloning: map VoiceStudio saved profiles → Fish `reference_id`. Strategy: (a) paste an existing Fish `reference_id` into a profile, (b) optional "upload reference to Fish" (explicit confirm dialog: *this sends your audio to Fish Audio*). Respect the existing `max_ref_seconds` / `ref_strategy` fields exposed by `GET /engines`.
- Output: request `wav`/`pcm` where possible to avoid a lossy decode; resample through existing `audio_io` helpers.
- Long text: reuse `chunked_tts` / `sentence_chunker`; add retry with backoff on 429/5xx, hard timeout, cancellation via `inference_cancellation`.
- Errors: map 401/402/429 to actionable messages via `core/failure.py` (bad key / out of credits / rate limit). Never include the key or full request body in logs (`log_safe`).
- Cost visibility: show per-job character count and an optional monthly soft cap in Settings (client-side guard; users can burn credits quickly in batch/dub runs).
- Dubbing/batch: add a concurrency cap (default 2) so a 50-video batch can't hammer the API. Fish returns 429 on hitting the account concurrency limit, so the cap is a setting and 429 backs off rather than failing the job.

### 3.3 Local-first controls (required)
- No key → engine hidden/unavailable; no probe traffic. Key present but engine not selected → no traffic.
- Settings panel "Fish Audio (cloud)": key field (write-only, stored via `set_secret`), model dropdown, **Test connection** (cheap authenticated GET, no text sent), and a one-time consent line: *text and any reference audio you synthesize are sent to Fish Audio*.
- Dedicated HTTPS-only client pinned to `api.fish.audio` (configurable host for self-hosted/proxy, `https` required unless loopback). Leave `outbound_http.py` untouched.
- Add the Fish host to whatever test enumerates sanctioned outbound calls (grep `tests/` for the egress/analytics guards) so CI stays green and the exception is explicit and documented in the engine page.
- Watermark/provenance: output goes through the existing `mark_synthetic` path like other engines.

## 4. Phase 2 — Local Qwen3-TTS on a 3070, then fine-tuning

### 4.1 Feasibility on 8 GB (third-party figures; measure on the 3070 and record in `docs/benchmarks.md`)
| Model | Inference (bf16/fp16) | Notes |
|---|---|---|
| Qwen3-TTS-12Hz-0.6B (Base / CustomVoice) | ~2–4 GB | Comfortable; primary target. |
| Qwen3-TTS-12Hz-1.7B (Base / CustomVoice / VoiceDesign) | ~5–8 GB | Tight; likely needs fp16/8-bit and no other engine resident. FlashAttention 2 is painful on Windows → plan for SDPA fallback. |
| Fine-tune 0.6B Base | LoRA ≈ 2.5–4 GB, full ≈ 6.6 GB+ (estimates disagree) | LoRA/small batch on 3070 is plausible; 1.7B fine-tune is **not** a 3070 job without 8-bit/offload. |
Upstream fine-tuning is documented for single-speaker adaptation of the Base models. Sources: [Qwen3-TTS FAQ](https://www.mintlify.com/QwenLM/Qwen3-TTS/resources/faq), [fine-tuning guide](https://mintlify.com/QwenLM/Qwen3-TTS/advanced/fine-tuning).

### 4.2 Engine (inference) — `ext/qwen3-tts`
```
backend/engines/qwen3_tts/{__init__.py, bootstrap.py, main.py}   # SubprocessBackend, own venv
docs/engines/qwen3-tts.md
```
- Mirror `moss_tts_v15` exactly: `OMNIVOICE_QWEN3_TTS_DIR` or one-click venv install (CUDA only, torch from the pinned cu12x index), sidecar over stdio, lazy weight download from Hugging Face on first synth (uses existing `token_resolver`/HF mirror logic).
- Variants selectable as separate catalogue entries: `0.6B-Base` (clone), `0.6B/1.7B-CustomVoice` (preset speakers), `1.7B-VoiceDesign` (`supports_voice_design=True`, `instruct_vocabulary="freeform"`). Default the picker to 0.6B on <10 GB cards.
- Languages: zh, en, ja, ko, de, fr, ru, pt, es, it (matches existing mlx-audio table; reuse the full-name mapping already at `tts_backend.py` ~L2767).
- Memory: declare `gpu_compat=("cuda","cpu")`; register VRAM estimate with `engine_memory`/`memory_budget` so loading it evicts the resident engine rather than OOMing. Add fp16/8-bit option and an OOM → actionable error ("close other engines / pick 0.6B").
- Do **not** change the `mlx-audio` `qwen3-tts` entry; the Mac path keeps working. Use a distinct id (`qwen3-tts-cuda`) to avoid the collision in `_curated_key`.
- Licence: Apache-2.0 expected; still add records to `backend/config/model_licenses.json` and pass `scripts/check_model_licenses.py`.
- Tests: stub sidecar (acceptance bar #5); no GPU in CI.

### 4.3 Training — `ext/qwen3-train` (design first, build second)
Keep it a **job**, not part of the generation path.
```
backend/training/
  datasets.py    build/validate datasets (reuse docs/data_preparation.md + services/audio_quality, segmentation, asr_backend for transcripts)
  qwen3_ft.py    launches upstream finetuning script in the qwen3 venv (subprocess, never in-process)
  jobs.py        uses core job queue + event bus; progress, cancel, resume, checkpoints
backend/api/routers/training.py      /training/datasets, /training/jobs (new router, auto-included)
data dir: <omnivoice_data>/finetune/<job_id>/{dataset,checkpoints,logs}
```
- Dataset flow: project/profile audio → VAD/segment → ASR transcript (human-editable) → quality filter (SNR, clipping, length, duplicates) → manifest JSONL in upstream's expected format. Reuses existing services; no new heavy deps in the app venv.
- Training: LoRA-first on 0.6B Base, batch/grad-accum/gradient-checkpointing presets tuned for 8 GB, bf16 where the 3070 supports it (it does, Ampere). Pre-flight: VRAM check via `memory_budget`, refuse with guidance if the chosen config won't fit; evict the active TTS engine before starting; block generation on the GPU while training runs (or run training only when idle).
- Output: checkpoint/adapters registered as a **voice/engine variant** the Qwen3 sidecar can load (`OMNIVOICE_QWEN3_TTS_CKPT` or a catalogue entry per fine-tune). Voices stay as normal profiles so Clone/Stories/Dub can use them.
- UI: a new "Train" page under `electron/src/renderer/src/features/training/` (dataset builder, job monitor, "use this voice"). Add as a new route only; don't touch existing pages. Gate behind a Settings toggle (experimental).
- Do not reuse or edit `omnivoice/training/` or `docs/training.md` beyond a cross-link; they train a different model.
- Eval: A/B sample generation before/after, CER via the existing ASR + `docs/evaluation.md` metrics.
- Risks: Windows + bitsandbytes/flash-attn wheels; upstream finetune script assumptions (single GPU, Linux paths); long runs vs. app sleep/updates → needs checkpoint/resume from day one.

### 4.4 Order of work
1. Spike (no repo changes): run Qwen3-TTS 0.6B and 1.7B on the 3070 outside the app; log VRAM/RTF; run upstream finetune on a tiny dataset. Decide the go/no-go sizes.
2. Inference sidecar + docs + tests.
3. Dataset builder (usable alone — also feeds P3).
4. Training job runner + router.
5. Train UI + "use fine-tuned voice".

## 6. Risks & mitigations
| Risk | Mitigation |
|---|---|
| Upstream churn (very active repo) breaks the fork | Additive files; regular `upstream/main` merges; registry edits are tiny and isolated. |
| Fish API/header changes (docs mid-migration) | Model name is a setting; pin behaviour in stubbed tests; one `client.py` to update. |
| Accidental data egress | Opt-in, consent text, key-gated, no probe traffic when unconfigured, explicit test in CI. |
| 8 GB VRAM OOM | Memory registration + eviction, 0.6B default, pre-flight checks, readable errors. |
| Dependency conflicts (`transformers` pins) | Separate venvs; never `uv sync --all-extras` in the app venv. |
| Windows build issues (flash-attn, bitsandbytes) | SDPA fallback; document tested wheel versions; spike first. |
| CI guards fail (licences, locale, docs-drift, changelog) | Do those items in the same PR as the code; run targeted tests locally. |
| Training corrupts/consumes user data | Writes only under `finetune/<job_id>/`; reads project audio read-only. |
