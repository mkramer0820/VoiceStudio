## What we found (with evidence)
1. **Learning rate.** The script default `2e-5` gives noise and a model that never emits its end token (Qwen3-TTS issue #39; several users). `2e-6` is Qwen's README step-3 value and the one users report working on the unfixed script. Epochs beyond 1 to 3 at 2e-6 can lose the end token again, so always listen to every epoch; the loss number does not predict quality.
2. **Real bugs in `finetuning/sft_12hz.py` at the pinned commit `022e286`** (issues #371, #278, #337, #384, #179; fix by fumyou13 in #179):
   - The text embeddings are not passed through `talker.text_projection`, which generation always applies (it is a trained 2-layer MLP, not an identity, also for 1.7B).
   - The talker inputs and labels are sliced by hand (`[:, :-1]`, `[:, 1:]`) and `ForCausalLMLoss` then shifts the labels again, so the talker, including the **end-of-speech token**, is trained one frame late.
   - The sub-talker gets the wrong hidden state and its labels are shifted a second time inside `forward_finetune`.
   - Low learning rates only hid this by barely changing the model. The runner's patch (`ALIGN_*` constants, `_aligned_sub_talker_loss`) follows fumyou13's fix and is applied to a copy under `/content/qwen3_patched/`; it is checked against the real pinned file (patches cleanly, compiles) and refuses to patch any other script. **It has not been proven in isolation:** run 2 changed the learning rate, the silence padding and the patch together.
   - The Baseten recipe ([basetenlabs/ml-cookbook, qwen3-tts-transformers](https://github.com/basetenlabs/ml-cookbook/tree/main/training-jobs/examples/qwen3-tts-transformers)) uses lr 5e-6, warmup plus cosine, a frozen speaker encoder, a held-out set and 12 epochs, but keeps the double shift and has no text projection, and claims the other sub-talker slice is "upstream-correct". The two camps disagree; only listening settles it. No audio samples exist in that repo.
3. **Speaker name case.** Qwen's inference looks the name up lowercased (`speaker.lower() in spk_id`), but `sft_12hz.py` stores it as typed, so `SS_Narrator` can never be found (`NotImplementedError: Speaker ... not implemented`). The runner now trains with `model_speaker_name(p)` (lowercase) and repairs old checkpoints with `fix_speaker_names` (keeps `config.json.orig`).
4. **accelerate 1.12 refuses `log_with="tensorboard"` without a directory.** The script passes none, so it crashes at start. The patched copy adds `project_dir=$VS_TENSORBOARD_DIR`. The official script writes no TensorBoard events anyway.
5. **Colab runtime traps.**
   - No official FlashAttention wheel exists for CUDA 13 / Python 3.13. An earlier runner compiled it from source automatically and wasted an hour of the owner's compute. Now: runtime check first (seconds), never compile unless `BUILD_FLASH_ATTN=True`, 25-minute cap per pip step, 90-minute cap on a requested build, SDPA fallback via a patched copy.
   - The working path: the community wheel `flash_attn-2.8.3+cu130torch2.11-cp313-cp313-linux_x86_64.whl` (mjun0812/flash-attention-prebuild-wheels release v0.9.4, 242 MB) given as `FLASH_WHEEL`; it only fits torch 2.11. `wheel_fits` checks Python, torch and CUDA from the file name before pip runs; if it does not fit, `USE_VENV='auto'` builds an isolated Python environment with uv (never exercised on Colab).
   - **Never upgrade torch inside the runtime.** The owner did once on advice from an earlier agent: it left torchvision/torchaudio behind (`operator torchvision::nms does not exist`, the root cause is now shown by `probe_module`) and then `CUDNN_STATUS_SUBLIBRARY_VERSION_MISMATCH`. The setup table now runs a real GPU convolution (`torch convolution (cuDNN)`) and `repair_torch_companions` fixes mismatched companions.
6. **Generation.** The repo has no stop control other than the model emitting its end token. The default `max_new_tokens` is 2048 (164 s). The runner limits samples with `max_tokens_for(text, pace)`: this narrator's slowest-5%-pace seconds per character from the training clips, times the text length, plus 15% and half a second (12.5 tokens per second). Hugging Face generation is slow here (about 4.5 tokens per second on the A100, the Python loop is the bottleneck), and **batching texts does not return the true per-text length** (all items came out at the batch's cap), so do not use batches to measure stopping.
7. **Control experiments that mattered.** Base model (voice clone path, `language='English'`) with flash attention and with SDPA both sounded great, so the environment and the flash wheel are fine. The fine-tuned checkpoint was bad. For the fine-tuned custom-voice path do **not** pass `language` (training used the language-neutral `nothink` prefix; `Auto` builds the same prefix).

## Rules that bit us (obey)
- **Before advising settings, read the model's code and its GitHub issues.** Do not call a script default "the official setting".
- **Tell the owner up front whether a change affects the Colab session they are running** and how to check the runner version.
- Never start Colab sessions, upload, train or spend compute units without the owner's explicit go for that step. Never touch `G:\` except the folder the owner names. Never push or open a PR unless told. No agent attribution in commits.
- Give copy-pasteable steps with full file paths; identify notebook cells by their content. Never leave stale notebooks beside new ones in a folder the owner uploads from.
- Never overwrite or delete data on Drive by default; "local" means Colab's `/content`, Drive is the backup.

## Environment traps
- Windows + Git Bash: large heredocs fail and backslash escapes (newline, double backslash) inside heredocs are eaten; write scripts with the file tool. CRLF files: edit with `newline=""`.
- A cell running a long generation cannot be interrupted quickly; give every test a hard limit. `grep -r` over the repo root times out; use `git grep`.
